# 后续候选路线（不作优先级结论）

| 候选 | 目的 | 预计工作量 | 外部依赖 | 风险 | 增量价值 |
|---|---|---|---|---|---|
| A. HTTPS 手机部署 | 真手机以 secure context 使用麦克风 | 小 | Vercel/Netlify/Cloudflare Pages 账号或等价托管；可选域名 | 后端跨域/WSS 配置与真机兼容 | 最快验证手机体验 |
| B. 真实云端 LLM | 替换复杂文本 MockPlanner | 中 | 已批准的供应商、API key、成本/隐私/失败策略 | 延迟、断网、提示注入；绝不能进入 P0 | 更自然的任务理解 |
| C. 本地 ASR（Sherpa/Vosk 等） | 降低 Web Speech 依赖并可控测量 | 中到大 | 目标设备性能、中文模型、麦克风测试 | 精度/延迟/部署复杂度 | 更稳定的语音路径研究 |
| D. 受保护硬件 Gateway | 建立真实控制前的可信安全边界 | 大 | 正式协议、底盘组、硬件/台架、安全负责人 | 最高安全风险，需 HIL/审计 | 为真实控制奠定必要基础 |
| E. ROS2 集成 | 对接机器人中间件/导航 | 大 | ROS2 topic/service 定义、仿真/实体平台 | 状态一致性与任务安全 | 扩展导航能力 |
| F. 真机兼容与可用性验收 | 验证 Android/iOS、权限、竖屏和网络 | 小到中 | 多种设备、局域网/HTTPS | 发现浏览器差异 | 让 Demo 的“手机优先”结论有证据 |

这些是可选路线，不代表项目总控已批准任何一项。无论选择 B、C、D 或 E，P0 的本地/可信安全快速通道和独立物理急停都必须保持。
