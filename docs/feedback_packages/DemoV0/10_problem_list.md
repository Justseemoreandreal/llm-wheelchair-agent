## H-01：缺失物理急停与真实执行链

- **描述**：P0 当前仅更改 Mock 或 simulated controller 的字符串状态。
- **复现**：点击“停下”可见 `MOTOR=LOCKED;BRAKE=ENGAGED`，但系统没有连接任何底盘。
- **影响/原因**：浏览器、ASR、网络和软件都不是独立安全回路；Demo 设计范围本身未包含硬件。
- **推荐处理**：由底盘安全设计提供独立物理急停、受控制动路径和硬件在环验收；软件只能作为补充。

## H-02：网关缺少硬件级安全边界

- **描述**：`/ws/control` 接收任何符合 schema 的 P0-P3 命令；没有身份认证、授权、TLS 强制、服务端 latch 或命令序列策略。
- **复现**：阅读 `backend/app/main.py` 可见 P0 后的后续 `move_forward` 会由 controller 执行；浏览器 latch 不能保护绕开浏览器的客户端。
- **影响/原因**：真实网络环境可被错误或恶意客户端绕过前端路由安全层。
- **推荐处理**：真实网关应把 P0 状态机、硬件 enable、授权、消息完整性、TLS/WSS、watchdog、审计和 fail-safe 都放在可信端；不得把浏览器当安全边界。

## M-01 至 M-05 复现与处理

- M-01：本次没有 Android/iOS/真麦克风设备；需按设备矩阵手测权限、interim、自动结束和竖屏布局。
- M-02：用真实环境测 ASR 首个 interim、误识别和网络断开；在安全阶段加入独立输入和物理保护。
- M-03：现有 plan/ACK 都有 mock/simulated 明示；接硬件前按正式接口替换，不能猜协议。
- M-04：模拟网关适合 Demo；下一阶段设计长连接、ACK 序列号、重连、超时和服务端安全状态机。
- M-05：重启 FastAPI 后 controller 回到初始内存状态；真实阶段需要受审计的控制器状态恢复与安全默认态。
